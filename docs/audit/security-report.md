# ExamTopics security audit

Reviewed 2026-11-15 against baseline `b19dbc6`. The evidence links use baseline line numbers. Use `git show b19dbc6:<path>` to inspect the reviewed version when a file has changed or been removed. The review covered application source, authorization boundaries, MongoDB queries, Google OAuth and Sheets integration, container build contexts, GitHub Actions, Go and Python utilities, tracked files, and dependency manifests. Live account settings and integration behavior require separately authorized verification. No Critical issue was confirmed from repository evidence.

## High

| ID | Finding and evidence | Impact and remediation |
|---|---|---|
| SEC-01 | **Stored script injection in question content.** An authenticated exam author can save images and publish exam content. The renderer interpolates image URLs directly into HTML attributes, including an inline fallback handler. The question and answer components insert that HTML into the DOM. [examRoutes.js:18–22](../../examtopics-backend/routes/examRoutes.js#L18) · [examService.js:53–65](../../examtopics-backend/services/examService.js#L53) · `examtopics-practice/src/utils/replaceImgPlaceholders.ts:16–29` · [CollapsibleQuestionText.tsx:27,42](../../examtopics-practice/src/components/CollapsibleQuestionText.tsx#L27) · [QuestionItem.tsx:290](../../examtopics-practice/src/components/QuestionItem.tsx#L290) | A published exam can affect visitors in the frontend origin, where the bearer token is stored. Render text, line breaks and images as React elements, allow only supported URL schemes, and use a React error handler for the local-image fallback. |
| SEC-02 | **Source-known fallback for the JWT signing key.** Signing and protected route verification use the same source default if the environment is missing the key. User identity used by protected endpoints comes from the verified token payload. [authService.js:7–8,56–67,89–109](../../examtopics-backend/services/authService.js#L7) · [progressController.js:33–38](../../examtopics-backend/controllers/progressController.js#L33) | Conditional on deployment using the fallback, an attacker can impersonate users and access or modify their data. Fail closed on missing or known development-only signing keys in production. Verify staging uses a distinct key. Rotate any deployed fallback as a separately authorized operation. |
| SEC-03 | **Unbounded bearer renewal.** The refresh endpoint accepts a signed access token independently of its expiration and issues another seven-day token. There is no absolute session bound, renewal credential or revocation check in that flow. [authRoutes.js:10](../../examtopics-backend/routes/authRoutes.js#L10) · [authController.js:26–47](../../examtopics-backend/controllers/authController.js#L26) · [authService.js:70–83](../../examtopics-backend/services/authService.js#L70) | A captured token remains redeemable after its expected expiry and renewed tokens perpetuate access. Bound absolute session age and enforce a finite renewal window. A revocable, independently rotated refresh credential would support per-session invalidation. |
| SEC-04 | **Private exam questions can survive code reuse.** Exam deletion first deletes the owning record, then independently deletes child rows keyed only by the reusable exam code. Creation permits a free code, and reads authorize against its current parent before selecting child rows by code. [examService.js:176–203,236–261](../../examtopics-backend/services/examService.js#L176) · [Question.js:3–8,55–56](../../examtopics-backend/models/Question.js#L3) | Pending or failed cleanup can expose an old private exam's questions to another owner of the same code or to public viewers of a replacement published exam. Use immutable parent IDs for child reads and writes or transactional lifecycle operations that preserve atomic ownership and cleanup. Validate against a disposable replica set and handle existing orphan rows before activation. |

## Medium

| ID | Finding and evidence | Impact and remediation |
|---|---|---|
| SEC-05 | **OAuth callback is not correlated to the initiating browser session.** The Google strategy and route omit state verification. Production session cookies are marked secure, and the baseline Express setup has no explicit trust-proxy setting. [authService.js:24–29](../../examtopics-backend/services/authService.js#L24) · [authRoutes.js:7–8](../../examtopics-backend/routes/authRoutes.js#L7) · [index.js:49–59](../../examtopics-backend/index.js#L49) | Login CSRF can bind a browser to an unintended account. Correlate callbacks with short-lived browser-bound state and verify HTTPS cookie delivery and a successful login on the staging topology. |
| SEC-06 | **Bearer tokens travel in callback query strings and persist in local storage.** The callback redirects with a token in the query string, the frontend reads it, and the original navigation has no replace option. [authController.js:5–11](../../examtopics-backend/controllers/authController.js#L5) · [AuthCallback.tsx:12–26](../../examtopics-practice/src/components/AuthCallback.tsx#L12) · [AuthContext.tsx:31–32,110–120](../../examtopics-practice/src/contexts/AuthContext.tsx#L110) | Request logs and browser history can retain a reusable token. Any script running in the frontend origin can access the stored token. Use a single-use exchange code or HttpOnly cookies; disable caching and redact sensitive paths at HTTP logging boundaries. |
| SEC-07 | **Question mutation can race an ownership transfer.** The service reads and authorizes an exam, then updates the question independently using the code. A concurrent transfer changes the parent owner separately. [examService.js:125–145,281–289,339–343](../../examtopics-backend/services/examService.js#L125) | A former owner can complete an already-authorized edit after the transfer. Enforce the ownership invariant transactionally with a parent write or an equivalent ownership-version guard. |
| SEC-08 | **Anonymous integration writes and expensive requests lack application-layer controls.** Public reports append to Sheets with caller-provided fields. Global parsing accepts up to 25 MB, and unanswered cache misses on public health checks can each perform dependency requests. The public questions endpoint supports an unbounded result. [reportRoutes.js:5](../../examtopics-backend/routes/reportRoutes.js#L5) · [reportController.js:6–51](../../examtopics-backend/controllers/reportController.js#L6) · [index.js:46–47,61–67](../../examtopics-backend/index.js#L46) · [sheetsService.js:78–96](../../examtopics-backend/services/sheetsService.js#L78) · [examService.js:249–261](../../examtopics-backend/services/examService.js#L249) | Reports can consume quota and pollute the operator spreadsheet, while heavy requests can exhaust staging capacity. Add report-specific size and rate controls, cap or redesign full-exam reads with frontend coordination, and split cheap liveness from dependency readiness. Sheets appends already use `RAW`, which limits immediate formula interpretation. |
| SEC-09 | **Backend image can include local configuration or archive files.** The baseline Dockerfile copies the full context and the repository had no Docker ignore file. Git ignore rules cover environment and client credential files, but do not filter Docker contexts. The context also contains a tracked encrypted archive. [Dockerfile:6–13](../../examtopics-backend/Dockerfile#L6) · [.gitignore:7–12,64–68](../../examtopics-backend/.gitignore#L7) · [backend workflow:28–35](../../.github/workflows/deploy-backend.yml#L28) | A locally built and circulated image can disclose workspace material. Use an explicit runtime file allowlist and exclude secrets, archives and build artifacts from contexts. The presence of secrets in any published image was not verified. |
| SEC-10 | **Render deploy workflows use mutable action tags and push-triggered production deploys.** Backend uses tagged actions with access to publication/deployment credentials. Backend and frontend workflows invoke Render on matching `master` pushes or manual dispatch, with no environment gate declared in YAML. [deploy-backend.yml:3–9,15–44](../../.github/workflows/deploy-backend.yml#L3) · [deploy.yml:3–21](../../.github/workflows/deploy.yml#L3) · [docker.yml:31–58](../../.github/workflows/docker.yml#L31) | Compromised action references or uncontrolled workflow dispatch can affect publishing and deployments. Pin reviewed full commit SHAs, use minimal workflow permissions, and verify actual branch and environment protections. Render workflow changes require separate approval. |
| SEC-11 | **Go downloader reaches an affected external HTML parser.** The manifest selects `golang.org/x/net v0.39.0`. The scraper parses remote responses with goquery, whose installed dependency implementation calls `html.Parse`. [go.mod:18](../../examtopics-downloader/go.mod#L18) · [fetch.go:50–63,106–117](../../examtopics-downloader/internal/fetch/fetch.go#L50) · [Go advisory GO-2026-4440](https://pkg.go.dev/vuln/GO-2026-4440) | A hostile HTML response can consume downloader CPU. Upgrade to a supported toolchain and patched module version after a full advisory scan, then add download size limits to bound memory usage independently. This is a downloader finding. |
| SEC-12 | **Local MongoDB Compose publishes a root-credential port on all interfaces.** The host mapping has no loopback address and the service includes known development credentials. [docker-compose.yml:5–13](../../examtopics-backend/docker-compose.yml#L5) · [migrate-samples.js:13–19](../../examtopics-backend/scripts/migrate-samples.js#L13) | A reachable development workstation or host could expose local database contents. Bind to loopback or remove host port publishing, load local-only credentials privately, and never reuse this Compose file in staging. No Atlas credential exposure was established. |
| SEC-13 | **Image downloader can place files outside its configured directory.** It derives directory components from remote URL paths in input JSON, appends them directly to the configured output path and writes a fetched image without a confinement check. [download_images.py:74–97,126–152,167–170](../../examtopics-img-downloader/download_images.py#L74) | Untrusted input can direct local filesystem writes outside the intended directory, subject to a successful image response and OS permissions. Resolve destinations beneath the configured root, reject unsafe path segments and validate redirects before fetching. |

## Verification limits

- The baseline registry audit reported zero frontend findings and two moderate backend entries for the dev-only path covered by SEC-17. The backend registry audit reported zero vulnerabilities after the SEC-17 patch.
- `govulncheck ./...` on Go 1.26.4 flagged 25 reachable advisories in `golang.org/x/net` and the standard library, including SEC-11. It identified 11 additional advisories in imported packages or required modules with no detected call. Upgrade the downloader toolchain and module together, then rerun the scan and tests. The current downloader Dockerfile and CI select Go 1.24.
- A pinned `pip-audit` scan of seven HTTP and parsing packages in the local Python test environment reported five advisory records across `certifi 2026.7.22` and `soupsieve 2.10`. Four advisory IDs were unique because `PYSEC-2026-4320` appeared twice. The tested `requests 2.34.2` had no advisories. These packages are for local Python tools outside the staging runtime.
- Targeted, filename-only credential-pattern checks on tracked text found documentation templates and a local migration URI. A redacted Gitleaks scan of 165 commits across local refs reported one generic-key match. Review of the source identified it as a historical service worker cache name. A redacted scan of changed files likewise reported one match, a synthetic ACM certificate ARN used by the Terraform mock. The scans skipped files above 15 MB. Encrypted archive contents, generated container images, remote-only refs and live secret stores remain unverified.
- Verify staging and production have distinct JWT and session keys, OAuth clients, Sheets service accounts and Atlas users and databases. Check Atlas network allowlists, database roles, TLS, backups and service integration from the intended staging account only after authorization. Live repository protections and deployed frontend headers were also outside this review.
