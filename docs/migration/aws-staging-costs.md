The $18 allowance includes headroom for modest traffic or request pricing variance and leaves $2 below the $20 ceiling before other account spending and taxes. It is a forecast, not verified account spend or a guarantee that credits cover every charge. The Terraform configuration uses a single VPC with an internet gateway, and avoids recurring NAT gateway, load balancer, remote access endpoint and AWS hosted zone fees. The estimate assumes the already-owned `finbert.ngo` domain and existing Cloudflare DNS with no new paid features, an isolated staging Atlas deployment covered by its existing tier, and no paid Google Workspace changes. Include domain renewal and any new DNS, Atlas, Google or package/registry costs in the approval proposal as applicable. CloudFront is configured for the standard pay-as-you-go distribution rather than a subscription plan. A Budget with its notification address configured tracks account-wide cost before credits and reports actual usage at 25%, 50%, 75% and 100% and forecast usage at 100%. It does not enforce a spending cap. Metered traffic, logs, retained objects or snapshots introduced later, taxes, shared allowance exhaustion and retained idle resources can increase spend. Record both incurred gross costs and the remaining verified credit balance. Measure spending and storage after every staging release. Propose teardown before the Free plan expires if the environment is no longer needed.

Stop if the AWS plan is inactive, expired or unverifiable, if verified remaining USD credits are below $20, if a required operation could upgrade the account or if current spend plus projected additions exceeds $20 for that month. The AWS estimate, alert state and Terraform validation cannot substitute for the verified plan state and exact approval. ## CI/CD allowance (activation proposal)

The $18 runtime model must also cover private state storage, the combined 2 GB frontend/release-artifact version cap, the 2 GB ECR cap and metered monitoring. Budget approximately seven Cost Explorer requests per successful release (three workflow checks plus four guarded deployment phases); 20 releases/month at $0.01/request adds about $1.40. Rollbacks and failed attempts need additional requests and consume the reserve; reduce release frequency or stop if headroom is exhausted. [Cost Explorer API pricing](https://aws.amazon.com/aws-cost-management/aws-cost-explorer/pricing/). These are workload assumptions requiring price and account verification before activation, not fresh account measurements.

The example gate uses $18 monthly usage, $1 billing-lag reserve and $0.50 deployment reserve, adding incurred gross spend to a prorated remainder of monthly usage. Storage checks include all current/noncurrent object versions and reserve new publication plus rollback writes. Retention does not expire current healthy artifacts or tagged images; reaching a cap blocks releases until separately approved cleanup. State versions and baseline storage must stay within the reviewed small-state allowance and be monitored by the operator. No traffic or API gate guarantees a hard billing cap.
